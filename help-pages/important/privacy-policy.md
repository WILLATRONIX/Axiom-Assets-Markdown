## Personal Data

When creating and account, some data is required to identify who you are. The required data to verify your account is simple:

-   **Email**
    -   The user's email. Used to identify the owner of an account.
-   **Provider ID**
    -   When signing in using OAuth, with for example Google, they provide a unique value to identify a user. This value is meaningless on its own.
-   **Email Validity**
    -   If the user has verified their email with the respective provider, this value will be true. With a valid email, a user can sign in using multiple methods.

Other values like password and username are created by the user.

Here are some examples of the data that would be stored when a user creates an account.

### Using Google OAuth:

| Data Type      | User Auth Data |
| -------------- | -------------- |
| Email Hash     | 5a9eb7a6...    |
| Google ID      | 28500792...    |
| Email Validity | true           |

### Creating an account directly:

| Data Type      | User Auth Data |
| -------------- | -------------- |
| Email Hash     | 5a9eb7a6...    |
| Password Hash  | 325196dd...    |
| Email Validity | false          |

The email is hashed to ensure data security, so that in a worst-case scenario, any leaked data is useless.

## Logging and Activity Monitoring

To maintain security, most actions are logged.

- Activity logs are retained for **up to** six months.
- Only the most recent one month of logs is readily accessible to staff.
- **After** one month, logs are compressed and archived to a secure remote storage server.
- All logs are permanently deleted after the six-month retention period.

### Who is being logged

Logs **are not** used for advertising and **will not** be shared to third parties.

## Cookies

Axiom Assets only uses cookies that are strictly required for the website to function. These cookies are essential for authentication, security and account functionality and cannot be disabled.

### Required Cookies

- Authentication Cookie
    - Used for login sessions and to verify users.

- Visitor Identification Cookie
    - A cookie assigned to each visitor to authenticate users who are not logged in. This cookie can also be used to associate two accounts that have been logged into a device with the same visitor identifier.

The Visitor Identification Cookie does not track users across third-party websites, nor is it used for advertising. It is a first-party cookie used for authentication and logging. The value used to identify you is a random value generated using the UUIDv4 standard which only has context within Axiom Asset Library's database.

### Cookie Retention

All user authentication cookies are set to expire seventy-two hours after they are sent to the client. You may delete this cookie, but you will be logged out.

Visitor identification cookies expire thirty days after they are sent to the client. Deleting this cookie will have no effect, but you will be provided a new visitor identifier on the next refresh. Expired cookies will also be replaced with a new identifier.

Visitor identifiers are stored in Axiom Asset Library's database for thirty days. Once an identifier is thirty days old, it is permanently deleted. Deleting your visitor identification cookie will not remove it from the database.

Account association via visitor identifiers is used exclusively for security, moderation, and abuse prevention.
